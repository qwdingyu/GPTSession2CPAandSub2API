# 高频 AI 工具 GitHub 调研与产品机会（2026-07-09）

## 调研边界

本次目标是跳出 `/convert`，寻找更高频、更有用户粘性、能真实解决问题、适合部署在 Cloudflare 上的轻量 AI 工具方向。

调研方式：

- 使用 GitHub CLI `gh search repos` 检索公开仓库。
- 优先看 star、fork、更新时间、README 中的产品定位。
- 对关键仓库尝试读取 README/LICENSE/package.json。
- GitHub Search API 后半段触发 rate limit，因此本文只记录已经拿到的事实，不补造未验证数据。

## 已验证的高热方向

### 1. Prompt Optimizer / 提示词优化器

代表项目：

- `linshenkx/prompt-optimizer`
  - stars：31944
  - forks：3725
  - 更新时间：2026-07-09
  - 语言：TypeScript
  - 描述：An AI prompt optimizer for writing better prompts and getting better AI results.
- `microsoft/PromptWizard`
  - stars：3897
  - forks：337
  - 更新时间：2026-07-09
  - 描述：Task-Aware Agent-driven Prompt Optimization Framework
- `gepa-ai/gepa`
  - stars：5584
  - 更新时间：2026-07-09
  - 描述：Optimize prompts, code, and more with AI-powered Reflective Text Evolution

用户问题：

- 不会写提示词。
- 同一个需求反复问 AI，但结果不稳定。
- 不知道如何把“想法”拆成角色、目标、上下文、约束、输出格式、验收标准。

用户粘性：高。

原因：

- 每次使用 AI 都可能需要优化 prompt。
- 用户会反复复制、改写、保存、复用 prompt。
- 适合形成“我的提示词库”和模板收藏。

适合本项目的低成本版本：

- 不直接做复杂 AI 自动优化器。
- 先做“本地 Prompt 结构化重写器”：
  - 输入一段自然语言需求。
  - 输出结构化 prompt：角色、任务、上下文、约束、输出格式、检查清单。
  - 提供场景模板：写代码、改文案、写 PRD、代码审查、翻译、图片生成。
- 可选：允许用户填自己的 API Key 调用模型，但默认提供离线模板化改写，保持轻量。

建议优先级：P0。

原因：使用频率高、实现成本低、与当前 AI 工具索引定位高度一致。

建议优先级：P0。

原因：非常高频、低成本、可快速上线，并能增强站点粘性。

### 3. Repo / 文档转 LLM 上下文包

代表项目：

- `jimmc414/onefilellm`
  - stars：1995
  - forks：176
  - 更新时间：2026-07-07
  - 描述：Specify a github or local repo, github pull request, arXiv or paper, Youtube transcript or documentation URL on the web and scrape into a text file and clipboard for easier LLM ingestion.
- `Doriandarko/RepoToTextForLLMs`
  - stars：790
  - forks：101
  - 描述：Automate the analysis of GitHub repositories for LLMs ... Outputs include analysis prompts.

用户问题：

- 想让 AI 理解一个 GitHub 仓库，但不知道该贴哪些文件。
- README、目录树、关键源码、配置文件散落，手工复制很麻烦。
- AI 上下文有限，需要把项目压成“可读上下文包”。

用户粘性：中高。

原因：

- 开发者、产品经理、独立开发者经常需要让 AI 分析项目。
- 与当前 Cloudflare 静态工具定位契合，但如果要抓 GitHub URL 会涉及联网。

适合本项目的低成本版本：

- 先做“本地文件夹上下文打包器”：
  - 用户选择本地文件夹。
  - 过滤二进制、图片、lock、大文件。
  - 输出目录树 + 文件内容合并 Markdown。
  - 估算字符数/token 粗略数。
  - 一键复制/下载 `.md`。
- 暂不做在线抓 GitHub，避免后端和跨域问题。

建议优先级：P1。

原因：真实痛点强，但比 Prompt 库复杂；仍可纯前端实现。

  - 用户粘贴导出的 ChatGPT/Claude 对话 JSON 或 Markdown。
  - 清理无关 metadata。
  - 输出 Markdown、纯文本、问答对 JSON。
  - 可选按角色分块、提取 prompt、提取 action items。
- 不做浏览器扩展抓取，先做本地文本/JSON 转换。

建议优先级：P1。

原因：与 `/convert` 的本地转换能力相似，复用现有架构成本低。

## 推荐优先级

### P0：Prompt 卡片库 + Prompt 结构化重写器

最推荐。

原因：

- GitHub 热度最高，`f/prompts.chat`、`PlexPt/awesome-chatgpt-prompts-zh`、`linshenkx/prompt-optimizer` 都证明需求很强。
- 使用频率高，用户会反复回来复制和改 prompt。
- 实现成本低，可以先不调用模型。
- 与当前站点“AI 工具索引”定位高度匹配。

建议 MVP：

1. `/prompts` 页面。
2. Prompt 模板卡片库：搜索、分类、复制。
3. Prompt Builder：输入任务目标，选择场景，生成结构化 prompt。
4. 本地收藏：localStorage。
5. 不复制第三方仓库内容，先做原创/改写模板。

### P1：Repo / 文档上下文打包器

推荐作为第二个核心工具。

原因：

- 开发者真实高频痛点。
- 可纯前端实现文件夹读取。
- 与 AI 编程、代码审查、项目分析强相关。

建议 MVP：

1. `/context-pack` 页面。
2. 选择本地文件夹。
3. 文件过滤规则。
4. 输出目录树 + 合并 Markdown。
5. 估算长度，复制/下载。

### P1：对话导出清洗器

推荐作为第三个工具。

原因：

- 与现有 `/convert` 同属“本地转换/清洗”。
- 可以复用文件读取、ZIP、质量报告、下载逻辑。

建议 MVP：

1. `/chat-cleaner` 页面。
2. 粘贴/上传 ChatGPT/Claude 导出文本或 JSON。
3. 输出 Markdown、纯文本、问答 JSON。
4. 提取 prompt、结论、TODO。

### P2：图片 Prompt Builder

适合作为内容型工具补充。

原因：

- 粘性强，但用户群更垂直。
- 可以低成本上线，但需要认真设计标签库。

### P2：图片 API Playground

暂缓。

原因：

- 需要外联和 API Key。
- 会改变站点安全边界。
- 适合未来单独明确“需要用户自带 key”的高级工具页。

## 最终建议

下一步最值得实施的是：

> **Prompt 卡片库 + Prompt 结构化重写器**

它比继续扩展 `/convert` 更能提升使用频率和用户粘性，也更符合“AI 工具索引 + 轻量实用工具聚合”的定位。

建议不要一开始做复杂 AI 调用，而是先做：

- 高质量中文 Prompt 模板。
- 结构化 Prompt Builder。
- 一键复制。
- 本地收藏。
- 分类搜索。

这样能在不增加后端、不增加密钥、不破坏 CSP 的情况下，快速提供真实价值。
