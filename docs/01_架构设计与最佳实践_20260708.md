# 01 架构设计与最佳实践

## 核心原则

1. **零服务器** — 纯静态，全在浏览器内执行，数据不上传
2. **单壳多工具** — 一份 HTML 壳（`run.html`）+ N 个工具模块（`tools/*.js`）
3. **渐进加载** — 首页轻（`index.html` ~4KB），工具按需加载

## 目录结构

```
src/
├── index.html          ← 导航首页（入口）
├── run.html            ← 工具壳页面（664B，不包含任何工具的 HTML）
├── run.js              ← 加载器：?tool=xxx → 动态注入工具模块
│
├── tools/
│   ├── convert.js      ← 工具模块：ChatGPT Session Converter
│   └── convert.css     ← 工具专属样式（可选，也可共用 style.css）
│   └── ...             ← 后续工具只需加 .js + 可选 .css
│
├── core/               ← 共享核心逻辑
│   ├── converter.js    ← 纯转换逻辑（不依赖 DOM）
│   ├── convert-app.js  ← 转换器 UI 绑定（依赖 DOM）
│   └── worker.js       ← Web Worker（离线程 JSON 解析）
│
├── app.js              ← 导航页交互（搜索、筛选）
├── style.css           ← 导航页样式（暗色主题）
├── tools-data.js       ← 46 个精选 AI 工具元数据
├── _headers            ← Cloudflare 安全头（CSP）
├── _redirects          ← Cloudflare 短链接规则
└── favicon.svg
```

## 为什么是最优方案

| 维度 | 目录×N 方案（❌） | 单壳+N 模块方案（✅） |
|------|------------------|---------------------|
| 新增工具成本 | 建目录 + 拷贝 HTML + 改路径 + 重复 CSS/JS | 1 个 .js 文件 + 1 行注册 |
| 页面总数 | N 个 HTML | 2 个 HTML（index + run） |
| 缓存效率 | 每工具独立 HTML，无法共享 | 公共壳缓存，模块单独缓存 |
| 路径管理 | 每工具一个子目录 | 统一 `/run.html?tool=xxx` 或 `/tool/xxx` |
| 本地调试 | 需启动服务器 | 直接双击 run.html?tool=convert 可用 |

## 数据流

```
┌─────────────┐     ┌──────────┐     ┌──────────────┐
│  index.html │────>│ run.html │────>│ tools/xxx.js │
│  (导航)     │     │ (?tool)  │     │ (initXxx)    │
└─────────────┘     └──────────┘     └──────┬───────┘
                                            │
                                   ┌────────▼───────┐
                                   │ core/xxx.js    │
                                   │ core/xxx-app.js│
                                   │ core/worker.js │
                                   └────────────────┘
```

## 文件约定

### 工具模块（`tools/xxx.js`）

```javascript
(function () {
  'use strict';

  // 1. 注册到全局 __TOOLS__
  window.__TOOLS__ = window.__TOOLS__ || {};
  window.__TOOLS__.xxx = {
    id: 'xxx',
    name: '工具名称',
    description: '一句话描述',
    icon: '...',       // 可选 SVG 字符串
    init: initModule,   // 入口函数
  };

  // 2. 入口函数：run.js 在加载完毕后调用
  function initModule(container) {
    // container === document.getElementById('tool-container')
    container.innerHTML = '';
    // 构建 UI、加载依赖、绑定事件
  }

})();
```

### 核心逻辑（`core/xxx.js`）

- 纯函数，零 DOM 依赖
- 通过 `window.FlowPilotConverter` 或 `window.MODULE_NAME` 暴露 API
- 单元测试友好

### UI 绑定（`core/xxx-app.js`）

- IIFE 自执行，操作 DOM
- 依赖 `core/xxx.js` 先加载

### 加载顺序（由 `tools/xxx.js` 控制）

```
tools/xxx.js (注册 init)
  └─ loadScript('./core/xxx.js')
       └─ loadScript('./core/xxx-app.js')
```

## 路径提示

| 文件位置 | 引用路径 |
|---------|---------|
| `run.html` → `run.js` | `./run.js` |
| `run.js` → `tools/convert.js` | `./tools/convert.js` |
| `tools/convert.js` → `core/converter.js` | `./core/converter.js` |
| `core/convert-app.js` → `core/worker.js` | `./core/worker.js` |

所有路径以 `run.html` 所在目录（`src/`）为基准。
