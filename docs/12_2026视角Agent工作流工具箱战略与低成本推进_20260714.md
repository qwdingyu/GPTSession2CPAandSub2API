# 2026 视角：Agent 工作流工具箱战略与低成本推进（2026-07-14）

## 背景修正

此前 `docs/11_高频AI工具GitHub调研与产品机会_20260709.md` 基于 GitHub 热度建议优先做“Prompt 卡片库 + Prompt 结构化重写器”。这个判断在“传统 ChatGPT 使用时代”成立，但从 2026 年 7 月的真实使用环境看，需要修正。

当前 AI 使用方式已经从“复制 prompt 给聊天框”进入到：

- Skill / Agent / Workflow 泛滥；
- Codex、Claude Code、Cursor、Cline、Windsurf、Devin 类工具成为高频入口；
- 用户不只是需要一段 prompt，而是需要可执行的上下文包、任务 brief、规则文件、验收标准、评估清单；
- prompt 模板库已经高度同质化，单纯卡片库很难形成壁垒。

因此，本项目不应把普通 Prompt 库作为核心差异化产品。Prompt 模板可以做，但只能作为 Agent 工作流工具箱的辅助能力。

## 新产品定位

> AI Forge 不只是 AI 工具索引，而是面向 AI Agent 时代的本地优先轻量工具箱：帮助用户把想法、项目、文件和对话整理成 Agent 可执行的任务资产。

核心价值从“给用户 prompt”升级为：

1. 帮用户准备 Agent 能理解的上下文；
2. 帮用户生成 Agent 可执行的任务 brief；
3. 帮用户把需求拆成 PRD / Issue / Test Spec / 验收标准；
4. 帮用户评估 AI 输出是否可执行、是否遗漏约束、是否可能幻觉；
5. 全程尽量本地处理，避免上传敏感项目和 token。

## 功能优先级重排

### P0：Context Pack Builder（上下文打包器）

#### 用户问题

Agent 经常失败，不是因为模型不够强，而是因为上下文给得不对：

- 用户不知道该给哪些文件；
- README、目录树、配置、关键源码分散；
- 手动复制容易漏文件、混入无关文件；
- 上下文太大，需要过滤和摘要；
- 需要把本地项目变成一个可发给 AI 的 Markdown 包。

#### 低成本 MVP

纯前端实现，不联网：

- 选择本地文件夹；
- 过滤 `.git`、`node_modules`、lock、大文件、图片、二进制；
- 输出目录树；
- 合并关键文本文件；
- 估算字符数和粗略 token 数；
- 一键复制/下载 Markdown；
- 后续可打包 ZIP 或保存 preset。

#### 为什么高价值

- 开发者、产品经理、运营都可能需要把资料交给 AI；
- 比普通 prompt 更难被替代；
- 与当前 `/convert` 的本地文件读取、ZIP、下载能力可复用；
- 不破坏 CSP 和隐私边界。

### P0：Agent Brief / Rule Generator（Agent 任务与规则生成器）

#### 用户问题

现在用户不是缺一句 prompt，而是不知道如何让 Agent 稳定完成任务：

- 任务边界不清；
- 验收标准缺失；
- 不知道怎么写 `AGENTS.md`、`CLAUDE.md`、Cursor Rules、Codex instructions；
- Agent 执行后难以判断是否完成。

#### 低成本 MVP

- 输入任务目标、项目类型、约束、期望输出；
- 生成：
  - Agent brief；
  - 任务步骤；
  - 验收标准；
  - 测试清单；
  - 风险/不做事项；
  - 可选 `AGENTS.md` / `CLAUDE.md` / Cursor Rules 片段。
- 先用模板规则生成，不调用模型。

#### 为什么高价值

- 直接服务 Codex/Claude Code/Cursor/Cline 用户；
- 生成的是“可执行任务资产”，不是泛泛 prompt；
- 粘性来自每个项目和每个任务都能用。

### P1：Prompt-to-Workflow Builder（提示词转工作流）

#### 用户问题

用户有一段自然语言需求，但不知道如何变成可复用流程。

#### MVP

- 输入原始需求；
- 输出工作流结构：触发条件、输入、处理步骤、输出、质量门禁；
- 可导出为 Skill 草稿、checklist、任务模板。

#### 与普通 Prompt 优化的区别

普通 prompt 优化只改写文字；Prompt-to-Workflow 生成的是可复用流程资产。

### P1：AI Output Evaluator（AI 输出评估器）

#### 用户问题

Agent 生成内容很多，但用户不知道是否：

- 跑题；
- 遗漏约束；
- 编造事实；
- 不可执行；
- 没有测试证据。

#### MVP

- 用户粘贴 AI 输出和原始任务；
- 本地 checklist 评估：完整性、可执行性、风险、证据、下一步；
- 输出“通过 / 需修改 / 高风险”报告。

### P2：Prompt 卡片库

#### 保留但降级

Prompt 卡片库可以作为辅助模块：

- 提供少量高质量原创模板；
- 嵌入 Agent Brief / Workflow Builder；
- 不作为主站核心卖点；
- 不复制未经许可的第三方 prompt 内容。

## 低成本高价值推进顺序

### 第一阶段：文档与信息架构纠偏

- 新增本文档，明确 2026 视角下的战略修正；
- 更新工具路线图，不再把普通 Prompt 库列为 P0 核心；
- 补齐系统架构图、运行机制、扩展维护文档。

### 第二阶段：Context Pack Builder MVP

新增 `/context-pack`：

- 本地文件夹选择；
- 过滤规则；
- 目录树生成；
- Markdown 输出；
- 复制/下载；
- 粗略 token 估算。

### 第三阶段：Agent Brief Generator MVP

新增 `/agent-brief`：

- 任务输入表单；
- 输出 Agent brief、验收标准、测试清单；
- 支持导出 Markdown。

### 第四阶段：AI Output Evaluator

新增 `/evaluate`：

- 输入原始任务和 AI 输出；
- checklist 本地评估；
- 输出风险报告。

## 明确不做

- 不做“系统提示词泄露库”；
- 不做默认联网 API Key Checker；
- 不默认上传代码仓库；
- 不把用户项目传给第三方模型；
- 不为了追热点做复杂后端平台。

## 与现有 `/convert` 的关系

`/convert` 是第一个成熟工具，证明了本项目适合做：

- 本地解析；
- 多格式兼容；
- 大批量处理；
- ZIP 下载；
- 质量报告；
- Cloudflare 静态部署。

未来工具应复用这些原则：

- 本地优先；
- 无依赖或少依赖；
- 明确隐私边界；
- 每个工具有清晰输入/处理/输出；
- 每个工具有测试 fixture 和文档矩阵。

## 结论

普通 Prompt 库在 2026 年已经不够差异化。本项目下一步应转向 **Agent 工作流工具箱**，优先实现 `Context Pack Builder` 和 `Agent Brief Generator`。这两个方向更贴近当下 Skill / Agent / Workflow 泛滥后的真实痛点，也更符合低成本高价值原则。
