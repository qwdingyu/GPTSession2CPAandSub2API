# AI Forge 工具收录标准与数据治理

> 目的：让 AI 工具索引从“链接列表”升级为“可信、可维护、可解释的工具目录”。

---

## 1. 为什么需要收录标准

AI 工具变化极快：产品改名、模型升级、价格变化、官网迁移、服务下线都很常见。如果没有收录标准，工具导航会很快变成过期链接集合。

中文注释：工具索引的核心竞争力不是“列得多”，而是“可信、清楚、能帮用户做选择”。

---

## 2. 收录原则

### 2.1 必须满足

- 有可访问的官方网站、官方文档或可信开源仓库。
- 工具用途明确，能归入现有分类或值得新增分类。
- 对用户有实际使用价值，而不是纯营销页。
- 不明显诱导用户提交敏感凭证到不可信站点。
- 名称、描述、链接应能通过人工核验。

### 2.2 优先收录

- 官方产品或主流开源项目。
- 有 API、文档、定价说明或开源许可证的工具。
- 在某一垂直场景中明显领先的工具。
- 对中文用户、开发者、创作者或企业用户有明确价值的工具。

### 2.3 谨慎收录

- 需要上传账号 token、cookie、session 的工具。
- 不清楚数据如何处理的代理类工具。
- 官网信息很少、只有邀请链接或营销页的工具。
- 价格、能力或模型名称频繁变化但缺少文档的工具。

### 2.4 不建议收录

- 明显仿冒官网。
- 诱导盗号、绕过付费、滥用账号的工具。
- 无法判断来源且要求用户输入敏感凭证的工具。
- 长期不可访问或停止维护的项目。

---

## 3. 推荐数据字段

当前 `src/tools-data.js` 已有字段：

```js
{
  id,
  name,
  description,
  category,
  url,
  icon,
  tags,
  featured
}
```

建议逐步扩展为：

```js
{
  id: 'openai',
  name: 'OpenAI',
  description: '简短说明，避免过度营销',
  category: 'llm',
  url: 'https://platform.openai.com',
  icon: '🤖',
  tags: ['API', '多模态'],

  // 是否首页推荐。推荐必须有推荐理由，避免“拍脑袋推荐”。
  featured: true,
  recommendReason: '模型能力、API 生态和文档成熟度综合领先。',

  // 面向人群，用于后续筛选。
  audience: ['developer', 'enterprise'],

  // 商业属性，用于用户快速判断成本。
  pricing: 'paid',

  // 工具形态，用于区分 SaaS、开源、API、桌面端等。
  productType: 'api-platform',

  // 使用风险或限制。
  cautions: ['价格与模型能力变化快，请以官方文档为准'],

  // 人工核验日期。
  lastCheckedAt: '2026-07-09',

  // 生命周期状态。
  status: 'active'
}
```

中文注释：字段不一定全部马上展示，但先让数据结构具备治理能力，未来才能做筛选、对比、排序和过期提醒。

---

## 4. 字段取值建议

### 4.1 `audience`

- `beginner`：适合 AI 新手。
- `developer`：适合开发者。
- `creator`：适合内容创作者。
- `researcher`：适合研究和学术。
- `enterprise`：适合企业或团队。

### 4.2 `pricing`

- `free`：主要功能免费。
- `free-trial`：有免费额度或试用。
- `paid`：主要功能付费。
- `open-source`：开源可自部署。
- `unknown`：暂未确认。

### 4.3 `productType`

- `web-app`：网页应用。
- `api-platform`：API 平台。
- `desktop-app`：桌面应用。
- `ide-plugin`：IDE 插件。
- `framework`：开发框架。
- `open-source-project`：开源项目。
- `local-tool`：本地工具。

### 4.4 `status`

- `active`：稳定推荐。
- `watching`：新工具，观察中。
- `risky`：有敏感凭证、合规或隐私风险，需要强提示。
- `deprecated`：不再推荐，仅保留记录。

---

## 5. 推荐规则

`featured: true` 不应只表示“我喜欢”，应至少满足以下条件之一：

- 行业内主流，用户认知度高。
- 在某个类别中能力明显领先。
- 文档、生态、稳定性明显更好。
- 对目标用户的实际效率提升明显。
- 与本站定位强相关。

同时必须填写：

- `recommendReason`
- `lastCheckedAt`
- 至少一个 `audience`
- 至少一个 `cautions` 或明确空数组

中文注释：推荐标签是产品信用的一部分，推荐理由越清楚，用户越信任。

---

## 6. 下架与降级规则

工具满足以下任一条件，应从 `featured` 中移除或标记为 `deprecated`：

- 官网连续多次不可访问。
- 产品停止维护或被并入其他产品。
- 明显存在安全风险且未修复。
- 主要能力被证实与描述严重不符。
- 收费、访问限制或使用条款发生重大变化，但页面仍保留旧描述。

中文注释：不一定要立即删除工具。对行业观察来说，“已过时/不再推荐”有时也有信息价值。

---

## 7. 更新流程

建议每次更新工具数据时遵循：

1. 检查官网链接是否仍可访问。
2. 确认工具名称是否变化。
3. 确认描述中模型名、功能名没有明显过时。
4. 更新 `lastCheckedAt`。
5. 如果设为推荐，补充 `recommendReason`。
6. 如果有风险，补充 `cautions`。
7. 本地打开页面，检查搜索、分类、推荐区显示正常。

---

## 8. AI Forge 自带本地工具的特殊规则

ChatGPT Session Converter 属于高敏感本地工具，建议使用更严格的标识：

```js
{
  productType: 'local-tool',
  status: 'risky',
  cautions: [
    '输入内容包含 access token，等同账号凭证',
    '转换结果也包含敏感凭证，不要上传、分享或提交到 Git',
    '本站应保持纯本地处理，不应新增远程上传能力'
  ]
}
```

中文注释：这里的 `risky` 不是说工具本身恶意，而是提醒“处理的数据风险等级高”。

---

## 9. 最小可执行改造建议

如果不想马上大改代码，建议先做三件小事：

1. 在 `tools-data.js` 给每个工具增加 `lastCheckedAt`。
2. 给所有 `featured: true` 的工具增加 `recommendReason`。
3. 在首页页脚显示“工具库最后核验日期”。

中文注释：这三件事成本低，但会显著提升用户对索引站的信任感。
