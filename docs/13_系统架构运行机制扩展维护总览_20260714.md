# 系统架构、运行机制、扩展与维护总览（2026-07-14）

## 系统定位

AI Forge 是部署在 Cloudflare Workers Static Assets 上的轻量本地优先 AI 工具箱。

当前已成熟的核心工具是 `/convert`，负责 ChatGPT Session / Codex auth / sub2api / CPA / Cockpit / 9router / AxonHub / Codex-Manager 等格式的本地转换。

未来方向是 Agent 工作流工具箱，当前已落地 Context Pack Builder、Agent Brief Generator、AI Output Evaluator、Prompt-to-Workflow Builder；后续能力继续按低成本高价值原则推进。

## `/convert` 运行机制

```text
输入 JSON / 文件 / 文件夹
  |
  v
convert-app.js
  |
  |-- 优先调用 Web Worker
  |-- Worker 不可用时 inline fallback
  v
worker.js
  |
  |-- importScripts('./converter.js')
  |-- 调用 FlowPilotConverter.parseSessionPayload
  v
converter.js
  |
  |-- detectFormat / findSessionCandidates
  |-- normalizeSessionRecord
  |-- buildSessionCompatibilityReport
  |-- buildZipArchive
  v
convert-app.js
  |
  |-- 渲染账号表格前 200 条预览
  |-- 渲染质量报告
  |-- 输出目标格式 JSON
  |-- 单文件或 ZIP 下载
```


## `Context Pack Builder` 运行机制

```text
选择本地文件夹
  |
  v
context-pack.js
  |-- File API 读取用户显式选择的文件
  |-- 跳过二进制、lock、大文件和构建目录
  v
core/context-pack.js
  |-- filterEntries
  |-- buildTree
  |-- buildContextMarkdown
  |-- estimateTokens
  v
Markdown 预览 / 复制 / 下载
```

维护原则：

- 不联网抓取 GitHub；
- 不上传用户项目文件；
- 默认保守过滤，避免误打包二进制和依赖目录；
- 新增过滤规则必须补测试。


## `Agent Brief Generator` 运行机制

```text
输入任务目标 / 上下文 / 约束
  |
  v
agent-brief.js
  |-- 收集表单输入
  |-- 切换输出视图
  v
core/agent-brief.js
  |-- normalizeInput
  |-- buildAgentBrief
  |-- 生成 brief / rules / issue / combined
  v
```

维护原则：

- 生成任务资产，不回退为普通 Prompt 模板库；
- 不调用模型，不要求 API Key；
- preset 变更必须补测试；
- 输出必须包含验收标准和验证命令。

## `AI Output Evaluator` 运行机制

```text
输入原始任务 / 需求清单 / AI 输出
  |
  v
evaluate.js
  |-- 收集表单输入
  |-- 调用本地评估内核
  |-- 渲染评分、发现项、Markdown 报告
  v
core/output-evaluator.js
  |-- 拆分验收标准
  |-- 归一化中英文文本
  |-- 匹配需求覆盖、验证证据、风险说明、文件引用
  |-- 输出结构评分和采纳建议
  v

```

维护原则：

- 只做本地启发式结构评估，不声称事实核验；
- 不调用模型，不要求 API Key；
- 中文需求匹配策略变更必须补测试；
- 报告必须保留“不能替代人工事实核验”的边界说明。

- 输出必须包含质量门禁和事实/推断边界。

## 核心模块职责

### `src/core/converter.js`

职责：纯业务内核。

包含：

- 格式检测；
- token/session 候选递归抽取；
- 统一账号归一化；
- 目标格式输出结构生成；
- 质量报告生成；
- 依赖最小的 ZIP store 模式生成器。

维护原则：

- 新格式优先加到这里；
- 保持纯函数，方便 Node 测试；
- 对业务边界、兼容策略、性能取舍写中文注释；
- 不把 DOM 操作、下载按钮逻辑、页面状态放进这里。

### `src/core/worker.js`

职责：Web Worker 桥接。

包含：

- 加载 `converter.js`；
- 接收 `parse-sessions` 消息；
- 回传进度、结果或错误。

维护原则：

- 只做桥接，不复制转换逻辑；
- 保持与 inline fallback 共用同一内核；
- 使用 `requestId` 避免旧结果覆盖新输入。

### `src/core/convert-app.js`

职责：页面 UI 编排。

包含：

- tab 和格式切换；
- 文件读取；
- Worker 调度；
- 输出构建；
- 表格预览；
- 质量报告渲染；
- ZIP 下载。

维护原则：

- 不新增业务格式转换分支；
- UI 只选择 `converter.js` 已生成的目标结构；
- 大批量 DOM 渲染必须限量；
- 敏感数据不上传、不外发。

### `src/_headers`

职责：安全响应头。

关键策略：

- `script-src 'self'`；
- `worker-src 'self' blob:`；
- `connect-src 'none'`；
- `object-src 'none'`；
- `frame-ancestors 'none'`。

维护原则：

- 除非新增明确需要联网的独立工具页，否则不要放宽 `connect-src 'none'`；
- 若未来某工具需要 API 调用，应单独设计安全边界和文档。

## 部署机制

```text
git push main
  |
  v
GitHub Actions: .github/workflows/deploy.yml
  |
  |-- checkout
  |-- setup-node@v4, Node 24
  |-- npm ci
  |-- npm run deploy:ci
        |
        |-- npm test
        |-- npm run check:static
        |-- wrangler deploy
        |-- npm run verify:domain
  v
Cloudflare Workers Static Assets
  |
  v
https://ai.eforge.xyz/
```

关键要求：

- `CLOUDFLARE_API_TOKEN` 已作为 GitHub Actions Secret 配置；
- Wrangler 版本由 `package-lock.json` 锁定；
- 部署后必须验证真实生产域名，而不是只看 wrangler 输出。

## 扩展新工具的标准流程

新增工具必须满足：

1. 明确用户问题和输入/输出；
2. 优先本地处理；
3. 不默认要求 API Key；
4. 不默认联网；
5. 有文档；
6. 有测试或至少静态验证；
7. 不破坏首页和 `/convert`；
8. 如涉及敏感数据，必须有显式风险提示。

推荐目录结构：

```text
src/<tool>.html
src/<tool>.js
src/tools/<tool>.css
src/core/<tool-core>.js   # 如果有纯函数核心
```

推荐文档：

```text
docs/<tool>-format-matrix.md
docs/fixtures/<tool>/...
docs/<tool>-implementation-notes.md
```

## 中文注释规范

不是所有代码都需要中文注释。需要注释的位置：

- 隐私边界；
- 安全策略；
- 格式兼容取舍；
- 大批量性能优化；
- ZIP / Worker / fallback 等容易误改的机制；
- 为什么不做某个看似自然的功能。

不需要注释的位置：

- 简单 DOM 查询；
- 直接赋值；
- 显而易见的循环和条件；
- 纯样式类切换。

## 已知暂缓项

- ZIP 输入解析：需要解压逻辑，当前文件夹选择 + 多 JSON 已覆盖主路径；
- 在线验活：会破坏本地隐私边界；
- 自动刷新 token：属于账号管理后端能力；
- 图片 API Playground：需要 API Key 和外联，后置；
- 普通 Prompt 卡片库：同质化严重，仅作为 Agent 工作流工具箱辅助。

## 维护清单

每次改动后至少检查：

- `npm test` 是否通过；
- `npm run check:static` 是否通过；
- `src/_headers` 是否仍符合隐私策略；
- 新增格式是否更新 `docs/convert-format-matrix.md`；
- 新增 fixture 是否加入测试；
- GitHub Actions 是否成功；
- `https://ai.eforge.xyz/` 是否可访问。
