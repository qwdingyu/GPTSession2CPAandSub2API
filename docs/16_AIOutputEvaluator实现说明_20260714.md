# AI Output Evaluator 实现说明（2026-07-14）

## 目标定位

AI Output Evaluator 是 Agent Workflow Toolbox 的第三个低成本高价值工具，用来解决一个高频痛点：用户拿到 AI / Agent 的最终输出后，难以快速判断它是否真正覆盖任务、是否给出验证证据、是否说明剩余风险。

它不是“再发明一个 Prompt 工具”，也不是自动事实核验器，而是一个本地 checklist 评估器：帮助用户把 AI 输出从“看起来完成了”转为“结构上是否可采纳”。

## 核心价值

- **采纳前复核**：检查输出是否覆盖原始需求、验收标准和关键约束。
- **验证证据提醒**：提示是否包含测试、构建、部署、域名验证等证据。
- **风险披露提醒**：提示是否说明未测试项、限制、剩余风险或 blocker。
- **本地隐私边界**：所有任务、需求和输出内容只在浏览器本地处理，不上传、不调用模型、不要求 API Key。
- **Markdown 留档**：可复制或下载评估报告，方便放入 PR、Issue 或交接文档。

## 文件结构

## 运行机制

```text
输入原始任务 / 需求清单 / AI 输出
  |
  v
src/evaluate.js
  |-- 收集文本输入
  |-- 调用 OutputEvaluator.evaluateOutput
  |-- 渲染评分、发现项、Markdown 报告
  v
src/core/output-evaluator.js
  |-- splitRequirements 拆分验收标准
  |-- normalizeForMatch 归一化中英文文本
  |-- requirementTerms 生成中英文匹配片段
  |-- 识别行动、验证、风险、文件引用信号
  |-- 计算结构评分和结论
  v
复制 / 下载 Markdown 报告
```

## 设计取舍

### 为什么不调用模型

当前项目明确坚持 local-first 和 privacy-first。AI 输出评估经常包含代码路径、部署信息、账号环境、业务细节甚至敏感任务上下文，如果默认发给外部模型，会破坏项目可信边界。

因此本工具只做启发式结构评估，不做事实判断。它能提醒“缺少验证证据”，但不会声称“测试真的通过”。

### 为什么不做复杂 NLP

该工具运行在 Cloudflare 静态资源和浏览器环境中，目标是轻量、低成本、可维护。复杂 NLP 会带来依赖、体积、联网或模型成本，不符合当前工具箱定位。

当前使用归一化文本 + 关键词 + 中文短片段匹配，优先覆盖 80% 高频场景：Agent 最终报告、PR 说明、部署回执、任务交接。

### 为什么保留人工判断

评分只代表输出结构质量，不代表事实真实性。用户仍需核对真实测试日志、部署结果、代码 diff 和生产域名访问结果。

## 中文注释原则

已在核心内核保留两类中文注释：

- 说明本地启发式评估的能力边界；
- 说明中文需求无空格分词时的保守匹配策略。

不在显而易见的 DOM 操作上堆叠注释，避免维护噪音。

## 验证覆盖

`test-output-evaluator.js` 覆盖：

- 高质量输出应获得 pass；
- 中文需求和命令型需求能够识别覆盖；
- 缺验证证据的短输出应 fail；
- Markdown 报告包含启发式评估免责声明；
- 报告包含需求覆盖清单。

## 后续可选增强

这些不是当前刚需，暂不实现：

- 导入 GitHub Actions 日志自动交叉验证；
- 多维度评分权重自定义；
- 团队模板化评估标准；
- 调用本地浏览器 AI 或用户自带 API 做语义复核。

如果未来要做，必须先明确隐私边界，不能破坏 `connect-src 'none'` 的默认安全策略。
