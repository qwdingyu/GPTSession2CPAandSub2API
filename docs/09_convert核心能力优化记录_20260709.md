# /convert 核心能力优化记录（2026-07-09）

## 背景与目标

`/convert` 的核心价值不是首页导航，而是把用户本地已有的 ChatGPT Session、CPA、sub2api、9router、Codex auth 等凭证数据，稳定转换成目标工具可导入的格式。

本次优化围绕刚需能力展开：

1. **多格式兼容**：兼容 ChatGPT Session、CPA、sub2api、9router/Codex OAuth 形态。
2. **多账号文件**：一个 JSON 文件中可以包含多组 token/session，工具应完整递归提取。
3. **大批量鲁棒性**：几千条 token 也要可解析、可转换、可验证，不因 UI fallback 与 Worker 逻辑分叉产生结果不一致。
4. **不发明轮子**：优先吸收开源项目的格式知识、样例和测试思路；不在许可证不清晰时复制代码。
5. **本地隐私优先**：继续保持浏览器本地处理，生产 CSP 的 `connect-src 'none'` 不应被弱化。

## 本次已落地的核心改动

### 1. 统一转换内核

此前存在两套 ChatGPT Session 转换实现：

- `src/core/worker.js`：Worker 线程中的抽取和转换逻辑。
- `src/core/convert-app.js`：Worker 不可用时的 inline fallback 逻辑。

这会导致两个风险：

- Worker 与 fallback 输出不一致。
- 修复一个路径后，另一路径继续保留旧 bug。

本次已将核心能力统一收敛到 `src/core/converter.js`：

- `findSessionCandidates(payload, options)`：递归扫描 JSON，抽取可转换 session/account 候选。
- `normalizeSessionRecord(record, options)`：把输入记录归一化为内部统一结构，并同时生成各目标格式。
- `parseSessionPayload(textOrPayload, options)`：完整解析入口，Worker 与 inline fallback 共用。

`src/core/worker.js` 现在只负责：

1. `importScripts('./converter.js')` 加载统一内核。
2. 调用 `FlowPilotConverter.parseSessionPayload(...)`。
3. 回传进度、结果或错误。

`src/core/convert-app.js` 现在只负责：

1. UI 状态管理。
2. Worker 调度。
3. Worker 不可用时调用同一个 `FlowPilotConverter.parseSessionPayload(...)`。
4. 根据用户选择输出 sub2api、CPA、Cockpit、9router、Codex auth。

### 2. 修复 9router fallback 输出不一致

此前 inline fallback 中：

```js
nineRouterAccount: sub2apiAccount
```

这会导致 Worker 路径生成的 9router 结构，与 fallback 路径生成的 9router 结构不一致。

现在 9router 输出由统一内核生成，包含：

- `platform: 'openai'`
- `type: 'oauth'`
- `credentials.client_id: 'codex'`
- `credentials.access_token`
- `credentials.refresh_token`
- `credentials.id_token`
- `extra.source`
- `extra.last_refresh`
- `extra.created_at`
- `extra.updated_at`

### 3. 增强大文件和多账号递归抽取

统一内核支持：

- 根对象就是单个 session。
- 数组中包含多个 session。
- `{ accounts: [...] }` 风格。
- 任意嵌套 JSON 中包含多组 session/account。
- token 位于 `accessToken`、`access_token`、`credentials.access_token`、`token.accessToken` 等常见位置。
- 身份信息位于 `user`、`email`、`name`、`account_id`、`chatgpt_account_id`、`providerSpecificData`、JWT claims 等常见位置。

递归扫描中跳过令牌字符串字段，避免对大体积 token 文本继续递归，降低大批量文件处理成本。

### 4. 增加 Worker 请求序号保护

`src/core/convert-app.js` 已增加 `requestId` / `workerSeq`。

目的：当用户快速连续输入或粘贴大文件时，旧 Worker 的异步结果不会覆盖新输入的结果。

这是大批量场景下非常关键的鲁棒性细节。

### 5. 增加批量回归测试

`test-converter.js` 新增覆盖：

- 单个 ChatGPT Session 转 CPA/sub2api/9router/Codex auth。
- 一个文件中嵌套多组 session。
- 9router-like 输入保持 9router 输出结构，而不是退化成 sub2api。
- 5000 条 session 的批量转换。

当前验证结果：

- `npm test`：67 passed, 0 failed。

## 中文注释说明

本次没有为了“注释数量”堆砌无价值注释，而是在核心风险点增加中文注释：

- `WeakSet` 防循环引用的原因。
- 跳过大 token 字符串递归的性能原因。
- 内部统一记录同时携带多种目标输出的架构原因。

后续原则：

- 对业务边界、隐私边界、格式兼容策略、性能取舍加中文注释。
- 不对显而易见的变量赋值、DOM 绑定、简单条件判断加噪音注释。

最佳实践不是直接复制代码，而是分层吸收：

1. **可直接吸收**：公开 README 中描述的格式约定、字段名、导入导出说明。
2. **可参考但需重写**：解析策略、测试样例思路、错误提示文案结构。
3. **不可直接复制**：许可证不明确或不兼容项目中的源码实现。
4. **必须记录来源**：若未来引入第三方样例、fixtures 或适配器，应在 docs 中记录 repo、文件、commit、license。

## 后续刚需优先级

### P0：格式兼容矩阵

建议补一个 `docs/convert-format-matrix.md`，逐项记录：

- 输入格式名称。
- 必需字段。
- 可选字段。
- 可推断字段。
- 不可恢复字段。
- 输出目标的字段映射。
- 已有测试样例。

### P0：真实开源样例 fixture

在许可证允许或仅手工重建的前提下，补充 fixtures：

- CPA 单账号。
- CPA `{ accounts: [] }`。
- sub2api 单账号。
- sub2api 数组。
- sub2api `{ accounts: [] }`。
- 9router OAuth 账号。
- Codex auth.json。
- ChatGPT session。
- 混合嵌套导出文件。

### P1：超大输出预览优化

当前 5000 条转换核心已验证，但 UI 仍会把完整 JSON 放进 textarea。

短期可接受，因为下载需要完整输出；但如果未来目标提升到 1 万条以上，建议：

- DOM 表格只渲染前 200 条预览。
- 输出预览只显示摘要和截断片段。
- 下载时再生成完整 JSON Blob。
- 显示格式兼容报告：缺 refresh_token、合成 id_token、缺 expires_at 等。

### P1：兼容报告

转换结果旁显示：

- 总账号数。
- 成功数。
- 跳过数。
- 缺失 refresh_token 数。
- 合成 id_token 数。
- 缺失 expiresAt 数。
- 识别到的 sourceType 分布。

这比增加导航标签更有价值，因为它直接帮助用户判断导入质量。

## 当前结论

本次优化后，`/convert` 的架构更接近最佳实践：

- 单一转换内核，避免 Worker/fallback 分叉。
- 多账号递归抽取能力增强。
- 9router 输出一致性问题已修复。
- 5000 条批量转换已纳入自动测试。
- 隐私边界未弱化，仍保持本地处理路线。

剩余最重要的工作不是 UI 堆功能，而是继续做格式矩阵、真实样例 fixtures、兼容报告和输出性能优化。
