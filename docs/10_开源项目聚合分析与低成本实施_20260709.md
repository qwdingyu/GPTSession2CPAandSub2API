# 开源项目聚合分析与低成本实施记录（2026-07-09）

## 目标

本项目的价值不是“再做一个导航页”，而是把 AI 工具链里分散、轻量、实用的 token/session 格式转换能力聚合起来，帮助用户在浏览器本地完成多格式转换、批量处理和导入前质量判断。

本次分析遵循三个原则：

1. **不产生幻觉**：只记录实际读取到的 README、LICENSE 或仓库元数据。
2. **不复制许可证不清晰的源码**：优先吸收格式说明、字段约定、测试思路；需要源码级复用时必须确认许可证。
3. **低成本高价值**：优先实现纯前端、无依赖、无后端、无联网、可测试的能力。

## 暂不实施内容与原因

### 1. 在线验活

不实施。

原因：

- 需要联网请求 OpenAI/Sub2API/第三方服务。
- 会破坏当前“完全本地处理”的隐私承诺。
- 会要求用户输入目标服务地址、API key、代理等配置，违背轻量工具定位。

替代方案：只做本地结构质量报告。

### 2. 自动刷新 token

不实施。

原因：

- refresh 流程涉及客户端凭证、网络请求、错误分类和安全存储。
- 很容易从“本地转换器”膨胀成账号管理后端。

替代方案：提示缺失 refresh_token、过期时间缺失、合成 id_token。

### 3. zip 解析/打包

本次不实施。

原因：

- 当前项目无额外依赖，保持 Cloudflare 静态部署简单。
- zip 解析需要引入库或复杂二进制处理。

替代方案：先支持文件夹选择和多 JSON 文件拖入；后续如果用户确实大量拿到 zip 包，再评估是否引入极小 zip 库。

### 4. 复制第三方源码

不实施。

原因：

- 部分仓库许可证不明。
- 本项目只需要格式知识和兼容目标，不需要复制实现。

替代方案：记录来源、重写适配器、补测试。

## 2026-07-09 追加实施：多账号 ZIP 打包下载

用户反馈“每账号单独下载”会一次弹出几十个甚至几千个浏览器下载，非常不友好。结合前序开源调研中 `account_*_sub2api_cpa.zip` 等真实包形态，本次优先实施**输出 ZIP 打包**，不实施 ZIP 输入解析。

### 已实施：浏览器本地 ZIP 生成

新增 `FlowPilotConverter.buildZipArchive(entries, options)`：

- 使用 ZIP store 模式（不压缩）生成标准 ZIP。
- 不新增 npm 依赖。
- 不联网，不上传 token。
- 支持 UTF-8 文件名。
- 为每个 entry 写入 CRC32、local header、central directory、end of central directory。

新增 `FlowPilotConverter.downloadZipFile(entries, fileName)`：

- 在浏览器本地生成 `application/zip` Blob。
- 只触发一次下载。
- 替代原先逐个 `setTimeout` 弹出多个下载的实现。

### 已实施：/convert 多账号下载改为 ZIP

当用户选择“每账号 ZIP”且转换结果超过 1 个账号时：

- 每个账号仍拆成独立 JSON 文件。
- 所有 JSON 被打包进一个 ZIP。
- ZIP 文件名为 `chatgpt_session_<format>_accounts.zip`。
- ZIP 内文件名包含序号和账号标识，例如 `0001_user_example.com_sub2api.json`。

### 已实施：文件互转批量下载改为 ZIP

“文件互转”区域如果一次转换多个文件：

- 单个结果仍直接下载 JSON。
- 多个结果打包为 `converted_accounts.zip`。

### 已验证

`test-converter.js` 新增 ZIP 生成测试，验证：

- ZIP local header 签名存在。
- ZIP 包含 entry 文件名。
- ZIP 包含 JSON payload。

当前测试结果：`103 passed, 0 failed`。

### 仍暂缓：ZIP 输入解析

ZIP 输入解析依然暂缓，原因不变：

- 需要二进制读取和解压逻辑。
- 可能引入依赖或较多复杂代码。
- 当前文件夹选择 + 多 JSON 拖入已经覆盖低成本主路径。

## 2026-07-09 追加实施：导入质量报告可视化

基于“导入前质量报告更可视化”的剩余低成本高价值项，本次将原先的纯文本缺字段提示升级为结构化摘要。

  - 结构较完整数。
  - 需关注数。
