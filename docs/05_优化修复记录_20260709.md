# 05 优化修复记录

## 日期：2026-07-09

## 修复清单

### 1. 首页 `index.html` 左右留白

- 在 `<main>` 标签中增加 `padding:0 8px`
- QQ 群导流区块增加 `padding:0 8px`
- 避免内容横向贴边

### 2. QQ 群导流 - 移除内联 `onclick`

**问题**：所有 QQ 群复制按钮使用了内联 `onclick`，在 convert.html 中 HTML 被截断显示残留的 JS 源码。

**修复**：
- 首页：删除内联 `onclick`，改用统一的 JS 事件委托（`app.js` 中通过 `document.addEventListener` 监听 `.qq-banner-copy` 点击）
- Convert 页面：两处 `banner-qq-copy` 均取消内联 `onclick`，改用 `convert-app.js` 中的事件委托
- 统一所有 `banner-qq-copy` 在复制成功后添加 `.copied` class -> CSS 控制视觉反馈

### 3. Web Worker 在 `file://` 崩溃

**问题**：`sub2api.json $: Failed to construct 'Worker': Script at 'file:///Users/.../worker.js' cannot be accessed from origin 'null'.`

**修复**：
- `getWorker()` 的 `try/catch` 已存在但 `worker.onerror` **没有降级**到内联处理
- 修改 `worker.onerror` 回调：自动设置 `USE_WORKER = false`，然后用 `runInline(text, sourceName, resolve, reject)` 重试
- 抽取 `runInline()` 函数避免冗余代码
- `workerPending` 增加 `text` / `sourceName` 字段供降级重试使用

### 4. 大 JSON 解析卡顿

**问题**：5000+ 个 token 的大文件会卡死主线程。

**优化**：
- 在 `parseSessionsInline` 的递归 `visit()` 中每 5000 次访问调用 `showProgress()` 让 UI 有机会更新
- 避免长时间占用主线程

### 5. 返回按钮在 `file://` 下显示文件索引

**问题**：`file:///Users/.../src/run.html?tool=convert` -> 页面跳转 -> 返回时浏览器展示目录列表。

**修复**：
- `run.js`：重定向从 `window.location.href = './convert.html'` 改为 `window.location.replace('convert.html')`，避免在历史堆栈中创建多余条目
- `run.js` 和 `convert.html` 中的返回链接统一从 `./index.html` 改为 `index.html`，路径解析更可靠

### 6. 多 Token 下载方式优化

- 下载方式选项从 "单个文件 / 每账号单独下载" 改为 "全部合并 / 每账号单独"（语义更清晰）
- 当有多个账号时显示账号计数（`dl-count`）
- 下载后输出状态提示：单文件模式显示"已下载 N 个账号的合并文件"，多文件模式显示"正在下载 N 个文件..."

### 7. Convert 页面样式美化

- 重写 `convert.css`，修复 `mask-image` 未加 `-webkit-` 前缀的问题
- 重新组织 CSS 结构，删除重复/无效规则
- 修复 `.panel-head` 支持子元素为 flex 布局（适配输出栏带按钮的场景）
- 修复 `.json-toggle` 激活状态样式
- 整体视觉更清爽、间距更合理

## 06 GitHub Actions 自动部署（已更新为 Node 24 + npm scripts）

> 2026-07-09 后续修正：本节早期曾使用 `cloudflare/wrangler-action@v3` 示例；该方案已因 Node 20 弃用风险废弃。当前以 `.github/workflows/deploy.yml` 与 `docs/08_GitHubActions与Cloudflare部署最佳实践_20260709.md` 为准。

### 当前唯一长期发布路径

```text
push main -> GitHub Actions -> npm ci -> npm run deploy:ci -> https://ai.eforge.xyz/
```

`npm run deploy:ci` 会串联：

```text
npm test -> npm run check:static -> npm run deploy -> npm run verify:domain
```

### 必需配置

GitHub 仓库只需要配置一个 Action Secret：

```text
CLOUDFLARE_API_TOKEN
```

Token 应具备部署 Worker `gptsession2cpaandsub2api` 的权限。域名 `https://ai.eforge.xyz/` 已是生产验证目标，不要再使用旧 Pages 试点口径作为发布目标。

### 不再推荐

- 不再使用 `cloudflare/wrangler-action@v3` 作为主部署路径。
- 不再使用 Node 20 或 `ACTIONS_ALLOW_USE_UNSECURE_NODE_VERSION=true` 作为长期方案。
- 不再依赖本地临时 `npx wrangler deploy` 作为常规发布动作。
- 不再把手动执行零散命令当作部署闭环。
