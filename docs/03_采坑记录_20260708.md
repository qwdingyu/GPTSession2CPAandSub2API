# 03 采坑记录

## 坑1：Cloudflare Pages 目录列表问题

**现象**：访问 `/convert` 时看到文件索引（目录列表），而不是页面。

**根因**：Cloudflare Pages 的 `html_handling: "auto-trailing-slash"` 只处理 `/about` → `/about/index.html` 模式，不做 `/convert` → `/convert/index.html` 的映射。当路径没有 `index.html` 或重写规则时，降级为目录列表。

**解决过程**：

| 尝试 | 结果 | 教训 |
|------|------|------|
| `convert/index.html` | 部分环境可用 | Cloudflare Pages 某些边缘节点仍然显示目录 |
| `convert.html` 根目录文件 | 本地 Live Server 不识别 | `_redirects` 只在 CF 部署时生效 |
| `_redirects` + `convert.html` | 路径不一致 | 本地和线上各走各的规则 |
| ✅ **`run.html?tool=xxx`** | 完全一致 | 查询参数在所有环境行为一致 |

**最终方案**：放弃子目录 + 多重入口，统一用 `run.html?tool=xxx`。

## 坑2：Web Worker 路径与 CSP

**现象**：Worker 加载报 `Blocked a script from loading because of Content Security Policy.`

**根因**：`_headers` 中的 CSP 没有允许 `worker-src`。

**修复**：

```diff
- Content-Security-Policy: ... script-src 'self' 'unsafe-inline' ...
+ Content-Security-Policy: ... script-src 'self' 'unsafe-inline'; worker-src 'self' blob:;
```

同时 Worker 路径必须相对于 HTML 页面，而不是相对于调用它的 JS 文件。在 `convert-app.js` 中：

```javascript
// 正确：相对于 run.html 的路径
new Worker('./core/worker.js');
// 错误（会报 404）：相对于 convert-app.js 的路径
// new Worker('./worker.js');
```

## 坑3：子目录下的 相对路径 陷阱

**现象**：将 `run.html` 放在 `convert/index.html` 时，所有 `./style.css` `./app.js` 引用都指向了 `convert/` 目录。

**根因**：HTML 文件路径是相对的，`convert/index.html` 的 `./` 是 `convert/`。

**解决**：将入口统一放在 `src/` 根目录，所有引用路径以根目录为基准。工具模块的路径按加载时的 HTML 位置计算。

## 坑4：双击 HTML 时的 Worker 限制

**现象**：`file://` 协议下 Double-click 打开页面，Worker 加载失败。

**根因**：`file://` 协议不支持 Web Worker（安全策略）。

**解决**：告知用户需通过本地服务器访问。最简单的方案：

```bash
# 使用 Live Server (VS Code)
# 或 Python
python3 -m http.server 8080 -d src
# 或 Node.js
npx serve src -p 8080
```

## 坑5：inline HTML 转义

**现象**：工具模块的 HTML 字符串中包含 `${}` 模板字面量时与 ES6 语法冲突。

**解决**：使用 `+` 拼接字符串，避免模板字面量：

```javascript
// 不推荐（在 strict IIFE + var 环境下 Template literal 可能意外解析）
var html = `<div>${name}</div>`;

// 推荐
var html = '<div>' + name + '</div>';
```

## 坑6：`__TOOLS__` 命名冲突

**现象**：两个工具模块定义了相同的 ID。

**解决**：ID 采用 `kebab-case`（连字符命名法），tools-data.js 中工具 ID 全局唯一。注册时后加载的会覆盖先加载的，应避免。

## 坑7：Cloudflare _redirects 不支持 query string 参数匹配

**现象**：`/tool/* /run.html?tool=:splat 200` 在 CF Pages 分叉版本中不工作。

**确认**：Cloudflare Pages（非 Workers）的 `_redirects` 支持 `:splat` 通配符和查询参数。如有问题，降级为硬编码规则：

```
/tool/convert /run.html?tool=convert 200
/tool/beautify /run.html?tool=beautify 200
```
